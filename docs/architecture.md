# Architecture

```
            ┌────────────┐  HTTPS/JWT   ┌──────────────────────────────┐   ┌──────────────┐
 Browser ──▶│ Next.js UI │────────────▶│ FastAPI (auth, validation,   │──▶│ PostgreSQL   │
            └────────────┘              │ pipeline, audit log)         │   └──────────────┘
 n8n  ── service token (no approvals) ─▶│                              │──▶ storage/local (StorageAbstraction)
                                        └──────┬───────────┬──────────┘
                    providers (swappable)       │           │ argv-only subprocess allow-list
     LLM: mock | ollama | anthropic             ▼           ▼
     Voice: piper | macOS say | elevenlabs   ffmpeg/ffprobe   node → Remotion (isolated process)
     Avatar: static | musetalk | heygen
```

**Lesson state machine** (`backend/app/models`, `services/pipeline.py`): TOPIC_PENDING → RESEARCHING → SCRIPT_GENERATED → TECHNICAL_REVIEW → *(human)* SCRIPT_APPROVED → ASSETS_GENERATING → ASSETS_READY → RENDERING → QUALITY_CHECK → APPROVAL_PENDING → *(human)* APPROVED → SCHEDULED → PUBLISHED; FAILED from any stage.
Every completed stage writes `last_good_status`; `resume()` continues from there (max 3 retries). Assets are keyed by content hash so re-runs are idempotent. Scripts and storyboards are versioned rows.

**Safety invariants**
- LLM output is parsed into strict Pydantic models (`schemas/content.py`); invalid output is retried once then rejected, never stored.
- No LLM text is ever executed. Terminal scenes are display-only strings. Subprocesses take argv lists from a fixed allow-list (`security/subprocess_safe.py`).
- Research only fetches allow-listed hosts; CVE IDs in scripts must verify against NVD or technical validation fails; CVSS without a verified CVE fails.
- Storyboards and scene text are scanned for keys, tokens, passwords, emails and non-lab private IPs before assets are built.
- YouTube upload requires lesson status APPROVED **and** a human APPROVED decision row; defaults to private; refuses without OAuth credentials.
- Approvals need a human role; the n8n service token is refused.

**Render engines.** `ffmpeg` (default; Pillow-drawn slides, captions baked into frames, fade transitions, soft-sub track) and `remotion` (React compositions with real transitions, animated bullets, SVG diagrams). Both emit `lesson.mp4`, `subtitles.srt`, `render_manifest.json`, then pass the same ffprobe verification (codec, 1920×1080, 30 fps, A/V drift, duration, full decode, sha256).

**Deployment shapes**: (A) macOS local: `scripts/setup.sh && scripts/start.sh`; (B) Ubuntu VPS: docker compose + nginx; (C) hybrid: automation (n8n+API+DB) on the VPS, renders on your Mac pointing `DATABASE_URL`/storage at the VPS (or sync `storage/`).

## Repository map

| Path | Role |
|---|---|
| `backend/app/api` | FastAPI routes (`routes.py`) |
| `backend/app/services` | pipeline state machine, generation, research, claim checking, quality gate, narration, animation sync, rendering |
| `backend/app/providers` | swappable LLM (`mock`, `ollama`, `anthropic`), voice (`kokoro`, `piper`, `macos_say`, `elevenlabs`) and avatar (`static`, `heygen`, `musetalk`) providers |
| `backend/app/security` | auth (JWT + bcrypt), rate limiter, redaction, path guards, argv-only subprocess runner |
| `backend/app/workers/remotion_adapter.py` | calls the Node/Remotion renderer in `video-engine/` |
| `backend/app/cli` | `demo`, `import_lesson`, `motion_samples`, `calibrate_voice`, and live-service check scripts |
| `backend/migrations` | Alembic schema migrations |
| `frontend/` | Next.js dashboard |
| `video-engine/` | Remotion compositions (optional renderer; see [animation-engine.md](animation-engine.md)) |
| `automation/` | 13 n8n workflows generated by `generate_workflows.py` |
| `ai/` | LLM prompts and JSON schemas |
| `lab/` | intentionally vulnerable localhost-only demo app (see `lab/README.md`) |

## Verification status of deployment shapes

- **A. macOS local** — the maintainer's primary environment (macOS arm64, Python 3.13, Node 26, Postgres 16, ffmpeg 8). The backend test suite (307 tests) passed there during release preparation.
- **B/C. Docker and hybrid** — images were built on the maintainer's machine and Postgres reached healthy, but workflow import into n8n and end-to-end n8n runs were **not** verified (see `DEVELOPMENT_STATUS.md`). Treat as experimental.
- **Linux, Windows** — not tested by the maintainers. The scripts avoid macOS-only commands where practical, except the optional `macos_say` voice. Windows is unsupported.
