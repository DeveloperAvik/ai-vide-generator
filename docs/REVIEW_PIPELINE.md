# Source-backed technical review, claim checking and quality gate

## Flow
```
research (collect sources) -> script (writer model) -> technical_review:
    collect cited URLs -> regex validation (CVE/CVSS/refs) -> claim extraction + claim-to-source judging
    -> independent reviewer pass (2 chunks: technical, teaching) -> SCRIPT GATE (stored)
-> TECHNICAL_REVIEW  (human: resolve findings / claims, approve script)   approve_script re-runs the script gate
-> storyboard -> PRE-TTS GATE (stored) -> TTS -> audio duration check -> PRE-RENDER GATE (re-evaluated) -> render -> ffprobe check -> QC
-> human video approval -> publish (PRE-PUBLISH GATE re-evaluated, then the existing approval + credentials checks)
```
A blocked gate raises `GateStop`: the lesson stays at its last good status, **no retry is consumed**, `last_error` explains why, and the blocking result is stored.

## What is checked
* **Sources** (`services/research.py`): https only, host allow-list, DNS resolved and rejected if private/loopback/link-local/metadata, IP-literals rejected, every redirect hop re-validated, timeout, streamed size cap (`RESEARCH_MAX_BYTES`, default 2 MB), `robots.txt` honoured, content-type must be text/HTML. HTTP 200 is not enough: error pages and near-empty pages become `empty_content`. Stored per source: title, publisher, category, retrieval time, published/updated date (page metadata or `Last-Modified`, blank if unknown), best section, SHA-256 of the extracted text, status, full extracted text with `##` headings. Duplicates (same URL ignoring `#fragment`) are skipped.
  *Residual risk:* DNS can be re-resolved by the HTTP client at connect time (DNS rebinding). The allow-list of official hosts is the primary control; the IP check is defence in depth.
* **Claims** (`services/claims.py`): per script section the model lists claims; for each, the 3 most similar passages from the lesson's verified sources are retrieved deterministically; the model judges them. The server then enforces: the quote must appear verbatim in that source's stored text (else `needs_human_review`), the source id must belong to this lesson, a `supported` verdict whose quote shares < 30 % of the claim's terms is downgraded to `partially_supported`, confidence is capped at 0.9, and anything not fully supported needs a human. Claims invented by the model (not traceable to the section) are dropped. Status: `supported | partially_supported | unsupported | contradicted | needs_human_review`.
* **Reviewer** (`services/techreview.py`): structured JSON validated by Pydantic (`ReviewOut`). Severity -> blocking is decided by the server: `critical`, `high`, `medium` block; `low`, `info` do not (the model's own `blocks_approval` is ignored). Problem text is located verbatim in the script; if it is not found the finding is flagged. The reviewer never edits the script.
* **Gate** (`services/qualitygate.py`): required sections, demonstration, defence, conclusion, quiz, objectives coverage, placeholders, empty fields, repeated sentences, references (retrieved, https, allow-listed), review completed **and current** (same script version), reviewer not simulated in production, no unresolved Critical/High/Medium finding, no unsupported **critical** claim or any contradicted claim, human script approval newer than the script; storyboard preflight (length window, placeholders, empty narration, repetition, markup, unsupported real-world claims, drawable diagrams), estimated duration at the calibrated speaking speed, storyboard newer than script, demo/quiz/summary scenes. After TTS: measured audio length. After render: ffprobe length vs request and vs narration (existing checks).
  *Mock template exemption:* scripts generated by the mock LLM are exempt from the *depth* checks (word minimums, objective coverage) and the length window - same convention as before. A review by the mock LLM is stored with `simulated=true`, shown as such, and **refused when `APP_ENV=production`**.

## Human decisions
| Action | Who | Effect |
|---|---|---|
| Accept & apply a correction | admin/reviewer | replaces the quoted text (optionally your edited wording) and saves a **new script revision** (`change_note` records the finding); lesson returns to `SCRIPT_GENERATED`, review must be rerun |
| Reject a finding | admin/reviewer + note >= 10 chars | dismissed, kept in history |
| Waive a blocking finding | Medium: admin/reviewer; **Critical/High: admin only**; note >= 10 chars | accepted risk without changing the script |
| Accept / reject a claim | admin/reviewer + note | `accepted` unblocks a critical unsupported claim |
| Approve script | admin/reviewer | only if the script gate passes; the n8n service token can never approve or decide |
Decisions on identical text survive a rerun of the review for the same script version. Nothing is ever published automatically; the YouTube upload additionally requires the human video approval and still only uploads `private`.

## API (all under `/api`, Bearer token; decisions need a human role)
| Method & path | Purpose |
|---|---|
| `POST /lessons/{id}/research/verify` | re-fetch every URL cited by the latest script (202) |
| `POST /lessons/{id}/review/run` | start / rerun / resume the technical review of the current script (202; 409 if one is running or the lesson is not at a script stage) |
| `GET /lessons/{id}/review` | review state (`pending/running/failed/human_review_required/passed/approved_for_rendering`), runs, findings (`?all_versions=true`) |
| `GET /lessons/{id}/claims` | claims with status, evidence excerpt, source objects, `blocks` |
| `GET /lessons/{id}/sources/{sid}/text` | stored sections of one source |
| `POST /review/findings/{fid}/decision` | `{decision: accept\|reject\|waive, note, correction?}` |
| `POST /review/claims/{cid}/decision` | `{decision: accepted\|rejected, note}` |
| `GET /lessons/{id}/gate`, `POST /lessons/{id}/gate/evaluate?stage=script\|pre_tts` | latest stored results / evaluate now |
| `GET /lessons/{id}/revisions`, `GET /lessons/{id}/revisions/{v}` | script revision history and content |
`GET /lessons/{id}` now also returns `review` and richer `sources`.

## Run the reviewer locally
```
# whole lesson from a terminal (real local model; never waives/approves what the gate blocks)
cd backend && .venv/bin/python -m app.cli.real_review_e2e "SQL Injection Fundamentals" 5 qwen2.5:7b-instruct [reviewer-model]
```
Or in the dashboard: Lessons -> a lesson -> *Technical review & fact-checking* -> **Start review / Rerun review**. Tabs: Findings (severity filter, current vs suggested text, accept/reject/waive), Claims (evidence + source link), Sources (provenance, stored text), Quality gate (checklist), Revisions (field diff).

## Resume after a failure
A failed review (Ollama down, model missing, timeout, bad JSON) leaves a `failed` run with the error and no partial findings. Fix the cause (`ollama serve`, `ollama pull <model>`), then press **Rerun review**, or `POST /lessons/{id}/review/run`, or `POST /lessons/{id}/retry` (resumes the pipeline from the last good stage). A review that died with the process is treated as abandoned after 3x `REVIEWER_TIMEOUT_S`. Only one review can run per lesson (409 otherwise).

## Tests
`cd backend && .venv/bin/python -m pytest -q` (or `make test`). New files: `test_research_sources.py`, `test_claims.py`, `test_techreview.py`, `test_qualitygate.py`, `test_review_pipeline.py`; shared fixtures in `tests/helpers.py`. Tests never call a real model: `ScriptedLLM` returns scripted answers (not named `mock`, so its reviews are not flagged simulated - the tests say what they verify), and HTTP is intercepted with `httpx.MockTransport`. Real-model behaviour is covered only by the e2e CLI above.
